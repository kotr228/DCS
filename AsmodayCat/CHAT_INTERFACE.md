# ASMODAYCAT - CHAT INTERFACE IMPLEMENTATION (PHASE 7.1)

## 1. Огляд завдання
Наразі `ChatView` має лише базову розмітку (поле вводу, кнопки "Send" та "Clear"). Необхідно перетворити його на повноцінний інтерфейс взаємодії з ШІ-агентом. Чат повинен підтримувати потокове виведення тексту (streaming), рендеринг Markdown (з підсвічуванням синтаксису коду), а також візуалізувати внутрішні стани агента (наприклад, "Agent is thinking..." або "Using WebSearch Tool...").

## 2. Функціональні вимоги до Чату (FR)
*   **FR-CH1 (Streaming):** Відповіді від LLM повинні виводитися в чат посимвольно/потоково, а не цілим блоком після завершення генерації.
*   **FR-CH2 (Markdown & Code):** Повідомлення від асистента повинні рендеритися з підтримкою Markdown. Блоки коду повинні мати підсвічування синтаксису (Syntax Highlighting) та кнопку "Copy".
*   **FR-CH3 (Agent State Indicators):** Під час обробки запиту UI повинен показувати статус агента (наприклад, анімацію завантаження або текст виклику інструменту).
*   **FR-CH4 (Context Management):** Кнопка "Clear" повинна не лише очищати UI, але й надсилати команду в `AsmodayCat.Service` на скидання історії контексту для поточної сесії.

## 3. ДЕКОМПОЗИЦІЯ ТА ПОКРОКОВІ ТАСКИ (ІНСТРУКЦІЯ ДЛЯ CLAUDE)

**@Claude:** Це інструкція для реалізації логіки та UI чату. Виконуй кроки послідовно.

### Step 1: DTO та Моделі (AsmodayCat.Shared)
1. Створи `ChatMessageDto` з полями: `Id`, `Role` (User, Assistant, System), `Content`, `Timestamp`.
2. Створи `AgentStateDto` для передачі поточного статусу агента (Idle, Thinking, UsingTool, ToolName).

### Step 2: Обробка Streaming через IPC (AsmodayCat.Service -> AsmodayCat.UI)
1. Налаштуй механізм передачі потокових даних. Якщо використовується Named Pipes, реалізуй асинхронне читання чанків тексту. Якщо gRPC — використовуй Server Streaming RPC.
2. В `AsmodayCat.Service` створи обробник, який приймає запит з чату, передає його в `ILLMEngine` і транслює згенеровані токени назад у UI.

### Step 3: ViewModel Чату (AsmodayCat.UI)
1. Відкрий або створи `ChatViewModel`.
2. Додай `ObservableCollection<ChatMessageDto> Messages`.
3. Додай властивості `CurrentInputText` (зв'язана з TextBox) та `IsAgentBusy` (для блокування кнопки Send).
4. Реалізуй `SendCommand` (IAsyncRelayCommand):
   * Додає повідомлення користувача в `Messages`.
   * Очищає поле вводу.
   * Створює пусте повідомлення для Assistant.
   * Відправляє запит через IPC і підписується на стрім, додаючи нові токени до останнього повідомлення Assistant.
5. Реалізуй `ClearCommand` для очищення колекції та скидання контексту на бекенді.

### Step 4: Верстка XAML та рендеринг Markdown (AsmodayCat.UI)
1. Встанови NuGet-пакет `Markdig.Wpf` або `MdXaml` для підтримки Markdown у WPF.
2. У `ChatView.xaml` додай `ListView` або `ItemsControl` (ScrollViewer), прив'язаний до `Messages`.
3. Створи `DataTemplate` для повідомлень:
   * **User:** Повідомлення вирівняне по правому краю, акцентний колір фону (наприклад, пурпурний).
   * **Assistant:** Повідомлення вирівняне по лівому краю, темний фон, контент прив'язаний до Markdown-рендерера.
4. Під полем вводу додай текстовий блок (зв'язаний з `AgentState`), який стає видимим лише коли `IsAgentBusy == true` (наприклад, відображає іконку завантаження `MaterialDesignThemes` та текст інструменту).

## 4. ДОДАТОК: Підтримка мультимодальності та прикріплення файлів (File & Image Attachments)

### Додаткові Функціональні Вимоги (FR)
*   **FR-CH5 (File Attachments):** Користувач повинен мати можливість прикріпити один або декілька локальних файлів (зображення, текстові документи) до свого повідомлення за допомогою кнопки "Скріпка".
*   **FR-CH6 (Attachment Preview):** Перед відправкою повідомлення прикріплені файли повинні відображатися над полем вводу (як мініатюри для зображень або іконки з назвами для документів) із можливістю їх видалити.
*   **FR-CH7 (Multimodal Routing):** Якщо користувач надсилає запит із прикріпленим зображенням, `AsmodayCat.Core` повинен автоматично спрямувати цей запит до мультимодальної моделі (наприклад, `llava:7b`), якщо поточна модель не підтримує Computer Vision.
