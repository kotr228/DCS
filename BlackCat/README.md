# BlackCat Firewall

**Брандмауер з кватерніонним шифруванням та прямим P2P-тунелем**

[![.NET](https://img.shields.io/badge/.NET-8.0-512BD4)](https://dotnet.microsoft.com/)
[![Platform](https://img.shields.io/badge/Platform-Windows-blue.svg)](https://www.microsoft.com/windows)

BlackCat — брандмауер нового покоління з вбудованим зашифрованим P2P-тунелем. Програма перехоплює мережевий трафік, фільтрує його за правилами, а для довірених вузлів будує прямий UDP-канал з MQE-шифруванням (Modular Quaternion Encryption). Два екземпляри BlackCat з'єднуються напряму через NAT без стороннього сервера.

## Можливості

**Фільтрація трафіку**
- Перехоплення IP-пакетів через Raw Socket (потребує прав адміністратора)
- Правила Allow / Block / Tunnel з пріоритетами
- Фільтрація за IP (CIDR), портом, протоколом (TCP, UDP, ICMP), напрямком
- Моніторинг активних з'єднань і процесів в реальному часі

**Зашифрований P2P-тунель**
- Підключення через обмін кодами (IP:порт з STUN-сервера)
- UDP hole punching для роботи за NAT
- Шифрування кожного пакету алгоритмом MQE
- Keepalive кожні 5 секунд, автовідключення через 30 секунд простою
- Захист від replay-атак (часова мітка ±30 секунд)

**Авто-обмін інформацією**
- При підключенні програми автоматично обмінюються Black-ID через тунель
- Телефонна книга оновлюється без участі користувача
- Автоматичний тест тунелю: надсилається `hello.txt` після handshake

**Кастомний Chrome (borderless)**
- Всі вікна (`MainWindow`, `StartupWindow`, `RulesManagementWindow` тощо) без системної рамки
- `WindowStyle="None"` + `AllowsTransparency="True"`
- Кастомний заголовок з підтримкою перетягування (`DragMove()`)
- Кнопки мінімізації, максимізації, закриття зі стилями `ChromeButton` / `ChromeCloseButton`

**Високопродуктивний моніторинг трафіку (MVVM)**
- `TrafficChartViewModel` — MVVM ViewModel з `INotifyPropertyChanged`, власник усього стану графіків
- `CircularBuffer<T>` — O(1) кільцевий буфер для 60-секундної історії
- `BackgroundTrafficCollector` — фонова Task (1 Гц), P/Invoke поза UI-потоком → `ConcurrentQueue<TrafficDataPoint>`
- `DispatcherTimer` (50 мс / 20 Гц) дренує чергу — без `ObservableCollection.Clear()`
- Value-type struct-и `TrafficDataPoint` / `ProcessTrafficEntry` — нульовий GC-тиск

**Дзеркалювання директорій (інтеграція з DCS)**
- `BlackCatCommandService` — named pipe сервер `"BlackCatCommandPipe"` для прийому команд від DCS
- `DcsIntegrationService.SendDirectoryAsync()` — рекурсивна передача дерев директорій через MQE-тунель
- `IpcBridgeService` — коректно підключений до `MainWindow.xaml.cs`
- Вхідні файли зберігаються до `temp_files/{sourceBlackID}/{dirName}/`
- Протокол `DcsPacket` розширено: `FileMeta` пакети несуть `dirName` та `relativePath`

**Журналювання**
- SQLite база даних: вузли, події підключень, правила, статистика
- `temp_data/` — системні файли програми (node info JSON, метадані трансферів)
- `temp_files/` — файли отримані від пірів (включно з дзеркальованими директоріями)

## Архітектура

```
BlackCat.UI          — WPF інтерфейс (кастомний chrome, графіки MVVM, тунелі, P2P, логи)
BlackCat.Core        — Бізнес-логіка (фільтр, тунель, БД, сервіси, DCS-інтеграція)
BlackCat.NetworkCore — Мережевий рівень (Raw Socket, UDP тунель, STUN)
BlackCat.Crypto      — Шифрування MQE (кватерніони)
BlackCat.Shared      — Загальні моделі та перерахування
BlackCat.Service     — Windows Service для фонової роботи
```

### Потік пакету

```
Мережевий пакет
    → PacketInterceptor (Raw Socket)
    → FilterEngine (перевірка правил, CIDR)
        → Allow  → пропустити
        → Block  → відкинути + лог
        → Tunnel → MQECryptoService.Encrypt()
                     → UdpEncryptedTunnel.SendAsync()
                         → піровий вузол розшифровує та обробляє
```

## Швидкий старт

**Вимоги:**
- Windows 10/11
- .NET 8.0 Runtime
- Запуск від імені адміністратора (для Raw Socket)

**Перший запуск:**

1. Запустіть `BlackCat.UI.exe` від імені адміністратора
2. Перейдіть до **Налаштування** → створіть **Black-ID** (формат: `РОЛЬ-МІСТО-НАЗВА-КОД`)
3. Натисніть **Запустити** — брандмауер і UDP-сервер стартують
4. Перейдіть до вкладки **🕳️ P2P** для підключення до іншого вузла

## P2P підключення

Підключення відбувається через обмін **кодами-ендпоінтами** (IP:порт).

### Крок 1 — Отримати свій код

На вкладці **P2P**:
1. Натисніть **🔄 Отримати код** — програма запитає STUN-сервер і покаже ваш публічний endpoint (наприклад `81.162.255.205:54321`)
2. Натисніть **📋 Копіювати** і передайте цей код іншому учаснику (месенджер, телефон)

### Крок 2 — Ввести код піра і підключитися

1. Отримайте код від іншого учасника
2. Вставте його в поле ② та натисніть **🚀 З'єднати (30 сек)**
3. **Обидва учасники повинні натиснути кнопку приблизно одночасно** (±30 секунд)
4. Після успіху:
   - Статус змінюється на **Підключено ✓**
   - Програми автоматично обмінюються Black-ID через тунель
   - Вузол зберігається в телефонній книзі
   - Надсилається тестовий файл `hello_*.txt`

### Повторне підключення

Якщо вузол вже є в телефонній книзі — відкрийте вкладку **🕳️ Тунелі**, виберіть вузол і натисніть **🕳️ Перепідключити**. Програма спробує hole punch до збереженого endpoint (30 секунд).

> **Увага:** При кожному запуску NAT-роутер видає новий порт. Якщо перепідключення не вдається — обміняйтесь новими кодами на вкладці P2P.

## Обмін файлами

Файли передаються через **зашифрований MQE-тунель** автоматично та вручну.

### Автоматичний обмін при підключенні

Через 1 секунду після встановлення тунелю кожна сторона надсилає:
- `hello_{BlackID}_{час}.txt` з текстом "Привіт від X! З'єднання встановлено..."

Файл зберігається в `temp_files/` у одержувача.

### Формат пакету файлу

```
[0xBC][0x1E]                   — маркер типу (file transfer)
[4 байти LE]                   — довжина імені файлу
[ім'я файлу UTF-8]
[вміст файлу]
```

Весь пакет шифрується MQE перед відправкою.

### Папки

| Папка | Призначення |
|-------|-------------|
| `temp_files/` | Отримані від пірів файли (для користувача) |
| `temp_data/` | Системні дані: node info JSON, копії відправлених файлів, `.meta` файли |

Обидві папки створюються поряд з `BlackCat.UI.exe` при першому запуску.

## Телефонна книга

Вкладка **🕳️ Тунелі** показує збережені вузли (SQLite таблиця `PeerNodes`).

**Поля вузла:**

| Поле | Опис |
|------|------|
| Black-ID | Унікальний ідентифікатор (оновлюється автоматично після обміну node info) |
| P2P Endpoint IP | IP-адреса піра |
| P2P Endpoint Порт | UDP-порт (оновлюється при кожному підключенні) |
| Статус | Підключено / Відключено / Підключення... |
| Надіслано / Отримано | Байти за поточну сесію |
| Час з'єднання | Тривалість активного підключення |
| Останній Handshake | Дата і час успішного підключення |

**Логіка дедублікації:** пошук здійснюється за IP, а не за портом — порт змінюється при кожному перезапуску NAT.

## Black-ID

Black-ID — унікальний текстовий ідентифікатор вузла. Формат:

```
РОЛЬ-МІСТО-НАЗВА-КОД
```

Приклад: `MAIN-KYIV-SERVER-2N4D`

**Правила:**
- Компоненти розділені `-`
- Всі символи — латиниця верхнього регістру та цифри
- КОД — 4 символи (генерується з hardware fingerprint)

Black-ID створюється в **Налаштування → Black-ID** при першому запуску. Він передається пірам автоматично через тунель після підключення.

## Шифрування MQE

**Modular Quaternion Encryption (MQE)** — блоковий шифр на основі множення кватерніонів в кільці ℤ₂₅₆.

### Принцип роботи

**Генерація ключа:**
```
sessionKey = SHA256(masterSecret + timestamp)
K = Quaternion(hash[0], hash[1], hash[2], hash[3])
```

**Шифрування блоку (4 байти):**
```
C = P * K   (множення Гамільтона, mod 256)
```

**Розшифрування:**
```
K⁻¹ = K.ModularInverse(256)
P = C * K⁻¹
```

### Захист

| Механізм | Реалізація |
|----------|------------|
| Динамічний ключ | SHA256(secret + timestamp) — новий ключ для кожного пакету |
| Replay attack | Часова мітка ±30 секунд (`TIMESTAMP_VALIDITY_SECONDS = 30`) |
| Цілісність | SHA256 контрольна сума зашифрованих даних |
| Паддінг | PKCS7 до розміру, кратного 4 байтам |

### Keepalive

Keepalive-пакети (`0xFF`) **не проходять через MQE** — надсилаються як є кожні 5 секунд. Це дозволяє відрізнити keepalive від зашифрованих даних без декрипції.
